Train multi-vector models for smaller document representations with token-pooling-aware and Matryoshka training. This release also adds optional kernels for MaxSim, Ward clustering, and transformer backbones, native AWS Neuron inference, faster utilities, and fixes across encoding, training, and evaluation.

> [!TIP]
> I share much more about training multi-vector models with token-pooling-aware losses in my new [Token Pooling-Aware Training for Multi-Vector Embedding Models](https://huggingface.co/blog/token-pooling) blogpost. Give it a read!

## Token-pooling-aware training (#4286)

### Train for fewer document embeddings

Token pooling for multi-vector models merges similar document token embeddings to reduce the embeddings stored and scored during retrieval. With `MultiVectorTokenPoolingLoss`, you can now train the encoder for this compression so its document embeddings retain more useful information after pooling.

Wrap a retrieval loss with the pooling configurations you intend to deploy:

```python
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.losses import (
    CachedMultiVectorMultipleNegativesRankingLoss,
    MultiVectorTokenPoolingLoss,
)
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("answerdotai/ModernBERT-base")
pooling = HierarchicalTokenPooling(pool_factor=4)
base_loss = CachedMultiVectorMultipleNegativesRankingLoss(model, mini_batch_size=64)
loss = MultiVectorTokenPoolingLoss(
    model,
    base_loss,
    token_poolings=[None, pooling],
    weights=[0.5, 0.5],
)
```

Pass `loss` to `MultiVectorEncoderTrainer` to train on the average of the unpooled and factor-4 retrieval losses. Because both variants reuse the same encoder embeddings, training adds clustering and scoring work without another encoder pass.

A matched experiment compared two ModernBERT-base models with fresh 128-dimensional projections, trained on the same 120,000 MS MARCO triplets with seed 42:

| Training | Unpooled nDCG@10 | Factor-4 nDCG@10 | Unpooled score retained |
| --- | ---: | ---: | ---: |
| Ordinary | 51.84 | 49.03 | 94.6% |
| Pooling-aware | 52.39 | 51.23 | 97.8% |

Factor-4 pooling reduces the average document representation from 193.22 to 48.68 embeddings, while the pooling-aware model retains 97.8% of its unpooled score.

To compress documents with the trained example model, pass a pooler to `encode_document` or set the runtime default with `MultiVectorEncoder(..., token_pooling=...)`. By default, pooling leaves query embeddings unchanged:

```python
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("tomaarsen/mve-ModernBERT-base-token-pooling")
queries = model.encode_query(["Which planet is known as the Red Planet?"])
documents = model.encode_document(
    ["Mars has a reddish surface.", "Jupiter is the largest planet."],
    token_pooling=HierarchicalTokenPooling(pool_factor=4),
)
scores = model.similarity(queries, documents)
```

See the [blogpost](https://huggingface.co/blog/token-pooling) for the method and experiments, and the [training guide](https://sbert.net/examples/multi_vector_encoder/training/token_pooling/README.html) for complete scripts. ([#4286](https://github.com/huggingface/sentence-transformers/pull/4286))

### Adaptive token budgets

Choose one of three `HierarchicalTokenPooling` controls to match the document budget you want to deploy:

| Control | Effect |
| --- | --- |
| `pool_factor=4` | Keep approximately one quarter of each document's vectors. |
| `max_tokens=16` | Keep at most 16 vectors per document, including protected tokens. |
| `distance_threshold=...` | Allocate vectors according to embedding geometry using a shared Ward distance threshold. |

For an adaptive budget, calibrate a threshold from representative document embeddings so the pooler targets an average count while allocating vectors according to each document's content:

```python
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("tomaarsen/mve-ModernBERT-base-token-pooling")
calibration_documents = [
    "Mars is the fourth planet from the Sun and has a reddish surface.",
    "Jupiter is a gas giant with many moons and a prominent Great Red Spot.",
]
embeddings = model.encode_document(calibration_documents)
threshold = HierarchicalTokenPooling.calibrate_distance_threshold(embeddings, target_tokens=8)
pooling = HierarchicalTokenPooling(distance_threshold=threshold) if threshold is not None else None
compressed = model.encode_document(calibration_documents, token_pooling=pooling)
```

The threshold targets an average on the calibration sample, so individual documents can receive more or fewer vectors and another corpus can have a different average. If the sample already fits the budget, calibration returns `None` and no pooling is needed.

These controls also work without pooling-aware training, so you can try compression on an existing model and evaluate it by passing the poolers to multi-vector evaluators.

### Matryoshka training for multi-vector models

`MultiVectorMatryoshkaLoss` trains a model to retain retrieval quality when token embeddings are truncated. Wrap your retrieval loss with the dimensions you want to support:

```python
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.losses import (
    CachedMultiVectorMultipleNegativesRankingLoss,
    MultiVectorMatryoshkaLoss,
)

model = MultiVectorEncoder("answerdotai/ModernBERT-base")
base_loss = CachedMultiVectorMultipleNegativesRankingLoss(model, mini_batch_size=64)
loss = MultiVectorMatryoshkaLoss(
    model,
    base_loss,
    matryoshka_dims=[128, 64, 32],
    matryoshka_weights=[1 / 3] * 3,
)
```

After training, use the shorter vectors by passing `truncate_dim=64` to both `encode_query` and `encode_document`, or set that width as the model constructor default.

In a separate matched experiment with 30,000 MS MARCO triplets, Matryoshka training preserves more retrieval quality at 64 dimensions, measured by mean nDCG@10 (%) across 13 NanoBEIR datasets:

| Training | 128-dimensional nDCG@10 | 64-dimensional nDCG@10 | Full-width score retained |
| --- | ---: | ---: | ---: |
| Ordinary | 48.45 | 45.46 | 93.8% |
| Matryoshka | 48.95 | 47.11 | 96.2% |

Using 64 dimensions halves vector storage at unchanged precision, with retention measured against each model's own 128-dimensional score.

To train for fewer vectors and shorter dimensions together, wrap `MultiVectorMatryoshkaLoss` with `MultiVectorTokenPoolingLoss` so pooling happens before truncation. See the [Matryoshka guide](https://sbert.net/examples/multi_vector_encoder/training/matryoshka/README.html) for complete training and evaluation scripts.

## Optional kernels for MaxSim, token pooling, and transformer backbones (#4344)

With `use_kernels=True`, all four model types can use compatible Hub kernels to accelerate operations in their transformer backbones. For multi-vector models, the same setting also enables kernels for MaxSim and MeanMaxSim scoring, as well as the Ward clustering used in token pooling:

```python
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("lightonai/mLateOn", use_kernels=True)
queries = model.encode_query(["How can I reduce retrieval storage?"])
documents = model.encode_document(
    ["Token pooling merges similar document vectors before indexing."],
    token_pooling=HierarchicalTokenPooling(pool_factor=2),
)
scores = model.similarity(queries, documents)
```

Install the optional dependencies with `pip install "sentence-transformers[kernels]"` before enabling kernels. The default multi-vector providers target CUDA and require Triton for MaxSim acceleration, falling back to reference implementations when a compatible device or provider build is unavailable.

In the [Ward benchmark](https://sbert.net/docs/multi_vector_encoder/usage/kernels.html), the kernel reduces pooling time from 7.00 seconds with fastcluster to 1.02 seconds, about 6.9x faster, for 5,000 SciFact titles and abstracts. Including encoding, the improvement is smaller: 23.14 to 18.91 seconds, an 18% reduction with mLateOn, BF16, batch size 32, factor 2, and an RTX 3090.

Kernels are opt-in runtime settings, so enable them again when reloading a saved model. For finer control, pass a Transformers `KernelConfig` to choose providers separately for the backbone, scoring, and pooling operations, as described in the [kernel guide](https://sbert.net/docs/multi_vector_encoder/usage/kernels.html). ([#4344](https://github.com/huggingface/sentence-transformers/pull/4344))

## Native AWS Neuron inference (#4293)

After installing TorchNeuron in a supported AWS environment, set `device="neuron"` to run dense, cross-encoder, and multi-vector inference through the existing torch backend:

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="neuron")
embeddings = model.encode(["Native inference on AWS Neuron."])
```

For multi-process encoding, load the model on CPU in a fresh parent process so workers can use separate Neuron cores. See the [PR](https://github.com/huggingface/sentence-transformers/pull/4293) for setup and device-allocation details.

## Smaller Features

- **More efficient community detection:** a shared batched implementation reduces GPU memory use on large embedding collections and speeds up CPU clustering. ([#4342](https://github.com/huggingface/sentence-transformers/pull/4342))
- **Faster utilities on Apple Silicon:** community detection and hard-negative mining spend less time synchronizing with the device, improving runtime on MPS. ([#4265](https://github.com/huggingface/sentence-transformers/pull/4265), [#4290](https://github.com/huggingface/sentence-transformers/pull/4290))
- **Faster Hugging Face Dataset inputs:** batch conversion of Dataset columns reduces data preparation overhead in encoding, prediction, mining, and selected sampler and evaluator workflows. ([#4347](https://github.com/huggingface/sentence-transformers/pull/4347))
- **Clearer model merging diagnostics:** configuration errors explain incompatible inputs more clearly, while new benchmark examples help you compare merged checkpoints. ([#4315](https://github.com/huggingface/sentence-transformers/pull/4315))

## Compatibility Notes

- **Multi-vector loss scoring:** the four built-in contrastive and distillation losses now follow the model's similarity even with kernels disabled, so MeanMaxSim models use mean scores instead of the previous MaxSim sums. Check your contrastive scale and teacher-score convention when upgrading. To retain the old MaxSim behavior, set `similarity_fct` to `colbert_scores` for ranking losses, `colbert_scores_pairwise` for margin MSE, or `colbert_kd_scores` for KL distillation. ([#4344](https://github.com/huggingface/sentence-transformers/pull/4344))
- **Evaluation scores:** historical scores can change because reranking and paraphrase-mining now follow the model's similarity, while CrossEncoder and RRF normalize MAP/nDCG against all known positives. Unretrieved positives receive no credit, so scores reflect retrieval failures. ([#4252](https://github.com/huggingface/sentence-transformers/pull/4252), [#4268](https://github.com/huggingface/sentence-transformers/pull/4268), [#4313](https://github.com/huggingface/sentence-transformers/pull/4313), [#4054](https://github.com/huggingface/sentence-transformers/pull/4054), [#4114](https://github.com/huggingface/sentence-transformers/pull/4114))
- **Checkpointing names:** use `activation_checkpointing_enable`, `activation_checkpointing`, and `activation_checkpointing_kwargs` across supported Transformers versions, or keep the legacy gradient-checkpointing names in existing scripts. ([#4328](https://github.com/huggingface/sentence-transformers/pull/4328))
- **Saved compression settings:** a constructor `truncate_dim` is saved with the model, but `token_pooling` is a runtime default, so supply the pooler again after reload. ([#4286](https://github.com/huggingface/sentence-transformers/pull/4286))
- **Pooler normalization:** newly constructed hierarchical poolers normalize their output vectors by default. Older saved configurations without `normalize_embeddings` retain their unnormalized behavior to preserve compatibility with existing embeddings. ([#4286](https://github.com/huggingface/sentence-transformers/pull/4286))
